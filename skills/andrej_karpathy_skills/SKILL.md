# Andrej Karpathy Coding Rules (Original)
1. Think First. Understand the problem deeply before writing any code. Ask clarifying questions if ambiguous. Do not guess.
2. Simplicity First. Prefer the simplest possible solution. Avoid over-engineering, premature abstraction, unnecessary complexity, patterns, or layers.
3. Surgical Changes. Make minimal, targeted edits. Only modify what is necessary. Do not refactor unrelated code, reformat, delete comments, or "improve" unrelated parts.
4. Goal Driven. Focus on the explicit goal. Do not add extra features, error handling, or generality unless required. Implement only what solves the task.
5. Expose Tradeoffs. Clearly state assumptions, limitations, and alternatives. Do not hide complexity or uncertainty.
6. Clean & Readable. Write straightforward, linear, easy-to-follow code. Use clear naming. Avoid clever one-liners that hurt readability.
7. Iterative & Verifiable. Prefer small, testable increments. Ensure the solution can be validated easily.
