## 1. 项目概述

### 1.1 项目背景

基于 AFSIM 构建防空作战场景，研究杀伤链的构建与优化方法，重点解决目标分配问题（目标→传感器→武器的联合分配）。

### 1.2 红蓝双方配置

**红方（防御方）**
- 预警机 × 1（部署杀伤链管理系统）
- 战斗机 × N（N=5~15）
- 地面雷达 × M（M=3~10）
- 地空导弹武器系统 × K（K=2~10）
- 总规模：10~30个实体

**蓝方（进攻方）**
- 敌方战斗机群
- 敌方预警机（若有）
- 典型进攻编队

### 1.3 杀伤链管理系统功能需求

a. 根据当前态势确定打击目标（目标优先级排序）
b. 优选最合适的传感器和武器（空空导弹 + 地空导弹）
c. 管控雷达进入特定探测模式（停转、提高数据率等）
d. 管控地导武器进行发射拦截
e. 全过程监控、评估打击效果，决定是否重新打击
f. **动态调整** - 打击过程中遇动态变化时重新分配

## 3. 接口设计

### 3.1 AFSIM 通信接口

**通信方式：共享内存 + Event Pipe（低延迟）**

```
AFSIM 仿真进程
     ↓ (Event Pipe / 共享内存)
外部杀伤链管理层
     ↓ (UCI 命令)
AFSIM 控制接口
```

### 3.2 共享内存数据结构

关键数据区：
- 目标列表（Track Table）
- 传感器状态
- 武器状态
- 杀伤链状态

### 3.3 UCI 命令类型

- `TRACK_UPDATE` - 目标更新
- `WEAPON_ASSIGN` - 武器分配
- `SENSOR_CONTROL` - 传感器控制（模式切换）
- `ENGAGE_COMMAND` - 发射命令
- `ASSESSMENT_REQUEST` - 评估请求

## 4. 算法设计

### 4.1 目标分配问题模型

**输入：**
- 威胁目标集合 T = {t₁, t₂, ..., tₙ}
- 可用传感器集合 S = {s₁, s₂, ..., sₘ}
- 可用武器集合 W = {w₁, w₂, ..., wₖ}

**输出：**
- 目标-传感器-武器匹配方案

**约束：**
- 每个目标至少被一个传感器跟踪
- 每个目标被最多一个武器攻击（除非需要多发）
- 传感器-武器配对有效性

### 4.2 算法策略

**双层决策架构：**

| 层级 | 策略 | 适用场景 | 响应时间 |
|------|------|---------|---------|
| 第一层：规则引擎 | 基于启发式规则 | 紧急拦截、时间敏感 | < 10ms |
| 第二层：算法优化 | 整数规划/遗传算法 | 精细分配、非紧急 | < 1s |

**算法类型：**
- **B. 动态分配** - 时敏目标重新分配
- **C. 多目标优化** - 杀伤概率、拦截时间、资源消耗综合
- **D. 联合分配** - 传感器-武器联合配对

### 4.3 算法选型

| 问题 | 算法 | 说明 |
|------|------|------|
| 静态分配 | 匈牙利算法 / Munkres | O(n³)，用于基准对比 |
| 动态分配 | 贪心 + 局部搜索 | 快速响应 |
| 多目标 | NSGA-II / MOPSO | 帕累托最优解集 |
| 联合分配 | 混合整数规划 (MILP) | CPLEX / Gurobi / OR-Tools |

## 5. 评估指标

| 指标 | 说明 | 优化方向 |
|------|------|---------|
| 杀伤概率 | 单发/多发杀伤概率 | ↑ 越高越好 |
| 拦截时间 | 从发现到拦截的耗时 | ↓ 越短越好 |
| 重点区域保护成功率 | 核心资产受保护比例 | ↑ 越高越好 |
| 资源消耗 | 弹药消耗量 | ↓ 越少越好 |
| 成本效费比 | 消耗资源/杀伤目标 | ↓ 越低越好 |
| 综合拦截效能 | 按优先级加权综合 | ↑ 越高越好 |

## 7. 开发流程

### 7.1 OpenClaw + Claude Code 协同模式

```
用户（飞书）
    ↓
OpenClaw（我）
    ├── 决策：设计方案、规划任务
    ├── 调度：把任务交给 Claude Code
    └── 整合：汇总结果、反馈
         ↓ (exec + claude -p)
    Claude Code（执行代码）
         ↓
    结果反馈给 OpenClaw
```

### 7.2 开发阶段

1. **Phase 1：环境搭建**
   - AFSIM 环境验证
   - 共享内存接口开发
   - UCI 通信测试

2. **Phase 2：基础场景**
   - 红蓝双方场景配置
   - IADS C2 processor 配置
   - Event Pipe 数据流验证

3. **Phase 3：杀伤链管理核心**
   - 规则引擎实现
   - 目标分配算法（静态）
   - 多目标优化算法

4. **Phase 4：动态调整**
   - 实时重分配机制
   - 动态场景测试

5. **Phase 5：评估与可视化**
   - 指标计算模块
   - 数据可视化
   - 结果分析

## 8. 技术选型

| 组件 | 选择 | 原因 |
|------|------|------|
| 仿真框架 | AFSIM 2.9.0 | 成熟的 IADS C2 功能 |
